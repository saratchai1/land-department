# สถาปัตยกรรมและขอบเขตของเดโม่

## สถานะของระบบ

นี่คือเว็บต้นแบบสำหรับสาธิตแนวคิด **Intelligent Land Administration** จำนวน 6 โมดูล เป็นการทดสอบประสบการณ์ใช้งาน ขั้นตอนสอบทาน และการอธิบายผลจากข้อมูลจำลอง

เดโม่ไม่มี backend ของงานที่ดิน ไม่มีการเชื่อมฐานข้อมูลราชการ ไม่มีบัญชีผู้ใช้หรือสิทธิการเข้าถึงข้อมูลจริง และไม่มีการเรียก LLM, OCR หรือบริการ AI ภายนอก การคำนวณและการเปลี่ยนสถานะของกรณีตัวอย่างเกิดในเบราว์เซอร์

ตัวอย่างบุคคล เลขอ้างอิง แปลงที่ดิน ปริมาตรสามมิติ กิจกรรมทะเบียน ภาระงาน และสำนักงานเป็นสิ่งสมมติ ภาพแผนที่หรือแปลงไม่ได้ใช้ยืนยันตำแหน่งหรือเขตทางกฎหมาย

## เทคโนโลยีและการรันในเครื่อง

ใช้ HTML, CSS และ JavaScript แบบ ES modules โดยไม่มี runtime dependency ของเฟรมเวิร์ก ฝั่งเครื่องมือพัฒนาใช้ Node.js รุ่น 22 ขึ้นไป ผลลัพธ์ build เป็น static files ที่ไม่ต้องมี application server

```bash
npm run dev
npm run check
npm test
npm run build
```

- `npm run dev` เปิด static development server ที่พอร์ต `5173` โดยค่าเริ่มต้น เปลี่ยนได้ด้วยตัวแปร `PORT`
- `npm run check` ตรวจไวยากรณ์ JavaScript และไฟล์ที่อ้างจากหน้าเริ่มต้น ไม่ใช่การทดสอบพฤติกรรมในเบราว์เซอร์
- `npm test` เรียก Node.js test runner สำหรับกติกาและการคำนวณที่มีชุดทดสอบ
- `npm run build` สร้างโฟลเดอร์ `dist/` จาก `index.html`, `src/` และ `public/` โฟลเดอร์นี้เป็นผลลัพธ์ที่สร้างใหม่ได้

แยกกติกาและการคำนวณไว้ในโมดูลข้อมูลของ `src/` และส่วนแสดงผลไว้ใน `src/views/` เพื่อให้ทดสอบสูตรได้โดยไม่ต้องเปิดหน้าจอ ไฟล์ใน `docs/` อธิบายขอบเขตและการสาธิต ไม่ใช่ข้อมูลที่ใช้รับรองผลธุรกรรม

## การแบ่งหน้าที่

| ส่วน | หน้าที่ในเดโม่ | ขอบเขตที่ต้องรักษา |
| --- | --- | --- |
| Application shell | เมนู หน้าปัจจุบัน การเปลี่ยนมุมมอง และข้อความแสดงสถานะเดโม่ | ทุกหน้าต้องเข้าถึงได้ และการเปลี่ยนหน้าไม่ควรทำให้ผลตรวจของกรณีอื่นเสียหาย |
| Smart Registration | เปรียบเทียบข้อมูลตัวอย่างและตรวจเอกสารตามเงื่อนไข | ไม่กล่าวอ้างว่าอ่านไฟล์จริงหรืออนุมัติธุรกรรม |
| Survey QA | แสดงรูปแปลงและตรวจเงื่อนไขเชิงเรขาคณิตที่สาธิต | ผลเชิงเรขาคณิตไม่ใช่ข้อวินิจฉัยสิทธิหรือเขตที่ดิน |
| 3D Cadastre | เลือกชั้น เปิด/ปิดส่วนของแบบจำลอง และแสดงข้อมูลอ้างอิงจำลอง | แยกการมองเห็นพื้นที่ออกจากสถานะทางกฎหมาย |
| Smart Survey | ทดลองจัดทรัพยากรและคำนวณแผนจากสมมติฐาน | แสดงหน่วยและข้อจำกัดของสูตร ไม่ทำให้ผู้ใช้เข้าใจว่าเป็นการพยากรณ์ด้วยโมเดลที่ฝึกแล้ว |
| Anomaly Review | แสดงสัญญาณตามกติกาและบันทึกผลสอบทานจำลอง | ไม่เปลี่ยนสัญญาณให้เป็นคำกล่าวหาหรือข้อสรุปการทุจริต |
| Command Center | สรุปสถานะตัวอย่างและผลจำลองกำลังการทำงาน | แยกข้อมูลสถานะออกจากสถานการณ์คาดการณ์ และไม่แสดงค่าจำลองเป็นสถิติของกรม |

## หลักการของข้อมูลและสถานะ

- ใช้รหัสที่ระบุความเป็นข้อมูลจำลองชัดเจน และไม่สร้างเลขประจำตัวประชาชนหรือเลขเอกสารจริง
- ค่าที่แสดงต้องอธิบายที่มาได้จากข้อมูลตัวอย่าง กติกา หรือสูตรที่ใช้
- เมื่อผู้ใช้เปลี่ยนกรณีตัวอย่าง ผลตรวจเดิมต้องถูกล้างหรือคำนวณใหม่ ไม่ปะปนข้ามกรณี
- การบันทึกผลสอบทานเป็นการเปลี่ยนสถานะเฉพาะในเดโม่ ไม่มีผลไปยังระบบภายนอก
- สถานะอยู่ในเบราว์เซอร์ การเก็บในพื้นที่จัดเก็บของเบราว์เซอร์ หากมี ไม่ใช่ฐานข้อมูลส่วนกลางและไม่ทำให้ผู้ใช้ต่างเครื่องเห็นข้อมูลร่วมกัน
- คำสั่งรีเซ็ตต้องคืนข้อมูลและสถานะเดโม่สู่ชุดเริ่มต้น โดยไม่เปลี่ยนไฟล์ต้นฉบับหรือข้อมูลภายนอก
- หลีกเลี่ยงข้อมูลสุ่มที่ทำให้ผลสาธิตซ้ำไม่ได้ สำหรับชุดอินพุตและกติกาเดียวกัน ผลคำนวณควรเหมือนกัน

## วิธีคำนวณและการอธิบายผล

### การตรวจทะเบียน

กติกาตรวจเปรียบเทียบข้อมูลที่มีอยู่ในตัวอย่าง เช่น ผู้ถือสิทธิ เลขอ้างอิง พื้นที่ และเอกสารประกอบตามเงื่อนไข กติกาควรคืนเหตุผลที่อ่านเข้าใจได้ พร้อมชี้ข้อมูลคู่ที่นำมาเปรียบเทียบ

การผ่านกติกาในเดโม่หมายถึงไม่พบข้อขัดแย้งตามกติกาที่สาธิตเท่านั้น ไม่ได้หมายความว่าเอกสารแท้ บุคคลมีอำนาจทำธุรกรรม หรือมีคุณสมบัติครบตามกฎหมาย

### การตรวจรูปแปลง

การตรวจเรขาคณิตอาจครอบคลุมพื้นที่ รูปแปลงที่ตัดตัวเอง หรือพื้นที่ซ้อนทับ ขอบเขตจริงต้องพิจารณาระบบพิกัด หน่วย ความละเอียด และหลักฐานประกอบด้วย ค่าคลาดเคลื่อนที่ผู้ใช้ปรับในเดโม่เป็นสมมติฐานสาธิต ไม่ใช่ค่ามาตรฐานงานรังวัดของกรม

พื้นที่ว่างระหว่างรูปแปลงไม่ควรถูกสรุปว่าเป็นข้อผิดพลาดเสมอไป เพราะอาจเป็นองค์ประกอบที่ตั้งใจเว้นไว้ ส่วนรูปแปลงที่แตะขอบกันไม่ควรถูกนับเป็นการทับซ้อนที่มีพื้นที่บวก

### การจำลองทรัพยากรและคิว

การประเมินคิวต้องแสดงภาระงาน อัตรางานเข้า และกำลังการทำงานเป็นหน่วยเดียวกัน สูตรอย่างง่ายใช้เพื่ออธิบายความสัมพันธ์ ไม่ครอบคลุมการหยุดงาน ทักษะเฉพาะ ความพร้อมเอกสาร หรือการเดินทางทั้งหมด

หากกำลังการทำงานไม่มากกว่าอัตรางานเข้า ระบบควรแสดงว่าคิวสะสมยังไม่ลดลงภายใต้สมมติฐานนั้น แทนการแสดงวันเสร็จที่ไม่มีความหมายหรือหารด้วยศูนย์

### การแจ้งเตือนความผิดปกติ

สัญญาณของแต่ละกรณีถูกกำหนดไว้ในข้อมูลตัวอย่าง เดโม่รวมคะแนนจากน้ำหนักของสัญญาณที่เปิดใช้งานและกรองคิวตามคะแนน/สถานะ จึงไม่ได้ตรวจจับรูปแบบจากเหตุการณ์ดิบหรือประมวลผลธุรกรรมแบบต่อเนื่อง

ผลจากกติกาต้องบอกว่าข้อมูลส่วนใดทำให้เข้าเงื่อนไข ถ้าใช้ระดับความเสี่ยง ควรอธิบายว่าเป็นลำดับความสำคัญสำหรับสอบทาน ไม่ใช่ความน่าจะเป็นของการทุจริต

ผลสอบทานควรมีเหตุผลและสถานะที่แยกกัน เช่น มีคำอธิบายรองรับ ขอข้อมูลเพิ่ม หรือส่งตรวจเพิ่มเติม การบันทึกดังกล่าวในเดโม่ไม่ใช่ audit log ที่ทนต่อการแก้ไขดัดแปลง

## ข้อจำกัดที่ต้องแจ้งผู้ชม

1. ยังไม่ผ่านการรับรองจากกรมที่ดิน และไม่มีข้อมูลจากระบบงานจริง
2. ยังไม่ได้พิสูจน์ความแม่นยำของ OCR, AI หรือประสิทธิภาพการทำงานกับเอกสารจริง
3. แบบจำลองสามมิติใช้สื่อสารแนวคิด ไม่ใช่ทะเบียนสิทธิที่มีผลทางกฎหมาย
4. การคาดการณ์เป็นผลจากสมมติฐาน ไม่ใช่คำรับประกันผลลัพธ์หรือระยะเวลาดำเนินการ
5. สถานะและประวัติในเบราว์เซอร์เหมาะสำหรับสาธิต ไม่ใช่ระบบหลายผู้ใช้หรือบันทึกตรวจสอบที่ใช้เป็นหลักฐาน
6. การพร้อมนำไปทดลองใช้งานจริงต้องประเมินระบบเดิม ข้อมูล กระบวนงาน สิทธิการเข้าถึง และการควบคุมเพิ่มเติม

## ขั้นต่อไปสำหรับระบบนำร่อง

### 1. ยืนยันกระบวนงานและช่องว่างจริง

สัมภาษณ์เจ้าของงานและผู้ปฏิบัติงาน ดูขั้นตอนจริง ระบบที่ใช้อยู่ ประเภทข้อยกเว้น และจุดที่เกิดงานซ้ำ เลือกกระบวนงานเดียวหรือกลุ่มงานที่มีขอบเขตชัดเจนก่อน และตรวจว่าฟังก์ชันใดมีอยู่แล้ว

ผลส่งมอบที่ควรได้คือแผนผังกระบวนงาน รายการระบบ/ข้อมูลที่ต้องใช้ บทบาทผู้เกี่ยวข้อง และเกณฑ์จบงานของแต่ละขั้น

### 2. เตรียมข้อมูลทดสอบที่ได้รับอนุญาต

กำหนดวัตถุประสงค์การใช้ข้อมูล ผู้มีสิทธิเข้าถึง อายุการเก็บ และวิธีลดข้อมูลระบุตัวบุคคล สร้างชุดคำตอบอ้างอิงโดยผู้เชี่ยวชาญ แยกข้อมูลสำหรับปรับแต่งจากข้อมูลประเมินผล และเก็บกรณียากหรือข้อยกเว้นไว้ในชุดทดสอบด้วย

### 3. ออกแบบจุดเชื่อมต่อและระบบบันทึก

ออกแบบ API หรือวิธีแลกเปลี่ยนข้อมูลที่ระบบเดิมรองรับ เริ่มจากการอ่านข้อมูลเมื่อเพียงพอต่อวัตถุประสงค์ ระบุแหล่งข้อมูลหลัก รุ่นข้อมูล หน่วย ระบบพิกัด และเวลาที่ข้อมูลมีผล

หากต้องบันทึกผลกลับ ต้องกำหนดอำนาจผู้อนุมัติ การตรวจความถูกต้อง การป้องกันบันทึกซ้ำ การจัดการข้อผิดพลาด และวิธีกู้คืนก่อน ไม่ใช้สถานะจากเบราว์เซอร์เป็นข้อมูลหลัก

### 4. เพิ่มความสามารถทีละส่วน

- **งานเอกสาร:** เพิ่ม OCR/การดึงข้อมูลพร้อมตำแหน่งอ้างอิงในเอกสาร บันทึกรุ่นโมเดลและให้ผู้ตรวจแก้ไขได้ ทดลองบนข้อมูลที่ได้รับอนุญาตก่อนเชื่อมขั้นตอนจริง
- **งานรังวัด:** ใช้ไลบรารีเชิงพื้นที่ที่รองรับข้อมูลและระบบพิกัดที่ตกลงร่วมกัน กำหนดกติกาจากผู้เชี่ยวชาญ และทดสอบกรณีขอบที่สำคัญ
- **งานสามมิติ:** สร้าง schema ที่แยกวัตถุทางกายภาพ พื้นที่เชิงสิทธิ เอกสารอ้างอิง และสถานะการตรวจรับ ระบุสิ่งที่แบบจำลองยังไม่สามารถแสดงได้
- **งานจัดทีม:** เพิ่มข้อจำกัดเรื่องทักษะ พื้นที่รับผิดชอบ การเดินทาง การนัดหมาย และความพร้อมของคู่กรณี พร้อมเปิดให้ผู้จัดแผนแก้ไขเหตุผลได้
- **งานสอบทาน:** ให้เจ้าของงานตรวจและจัดรุ่นกติกา จำกัดสิทธิ์เห็นข้อมูล และวัดทั้งการแจ้งเตือนเกินจำเป็นและเรื่องสำคัญที่พลาด
- **งานบริหาร:** แยกข้อมูลจริงจากแบบจำลองสถานการณ์ เก็บผลพยากรณ์ก่อนรู้คำตอบจริง เพื่อประเมินความคลาดเคลื่อนได้อย่างตรงไปตรงมา

### 5. ทดสอบร่วมกับเจ้าหน้าที่ก่อนขยาย

เริ่มแบบ shadow mode เมื่อเหมาะสม ให้ระบบเสนอผลโดยไม่เปลี่ยนผลการทำงานจริง เก็บเวลาที่รวมภาระการสอบทาน ทบทวนกรณีที่ระบบผิด และเปรียบเทียบกับค่าฐานของกระบวนงาน

ตัดสินใจขยายจากหลักฐานตามเกณฑ์ที่ตกลงไว้ ไม่ใช้ความสวยของหน้าจอหรือความรวดเร็วของข้อมูลจำลองแทนผลทดสอบจริง ดูตัวชี้วัดที่เสนอใน [DEMO_GUIDE.md](DEMO_GUIDE.md)

- ตรวจว่าการเปลี่ยนกรณีและการรีเซ็ตไม่ทิ้งผลเก่าปะปนอยู่
- ตรวจมุมมองหน้าจอเล็ก การใช้แป้นพิมพ์ ป้ายกำกับ และความอ่านง่ายของข้อความไทย
- ตรวจว่าทุกหน้าระบุข้อมูลจำลองอย่างชัดเจน และไม่มีข้อความอ้างว่าเชื่อมระบบหรืออนุมัติสิทธิจริง
- ตรวจไฟล์ที่จะเผยแพร่ให้ไม่มีข้อมูลส่วนบุคคล คีย์บริการ หรือข้อมูลภายใน
